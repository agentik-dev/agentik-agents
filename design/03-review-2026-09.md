# design/03: Adversarial review round, 2026-09-05

Status: **FINDINGS FIXED, TESTED, AND PUSHED** (2026-09-05). Raw reviewer
notes: `design/03-review-2026-09/raw-findings.md`.

On 2026-09-05, five adversarial reviewers each audited one surface of
`claude-code-agents`. All five surfaces had reproducible defects. Every
finding below was reproduced against the running code, then fixed, then
committed.

The router shipped as version 0.4.0. Its test count rose from 67 to 87.
The cost-accounting suite rose from 45 to 50 tests. The live router now
answers a health check at 8 ok / 0 warn / 0 FAIL.

Reviewers worked one surface each. Reviewer 1 covered the CLI. Reviewer 2
covered the end-to-end flow and docs. Reviewer 3 covered the HTTP router
and reproduced 13 findings against stub backends. Reviewer 4 covered the
shell tools and cost accounting. Reviewer 5 covered the plugin's agent,
command, and skill files.

Each reviewer got the same brief: assume the code is broken, cite file and
line, and reproduce a finding before reporting it. Excluded up front:
command namespacing, the Remote Control trade-off, and one pre-existing
failing check in `tests/test-fanout.py`. That check is unrelated to this
round.

The findings below group by what they have in common, not by which
reviewer found them. Four kinds recur. Credentials leaked, or requests went
to the wrong place. Failures happened without saying so. Systems hung or
crashed. Docs claimed things measurement did not back up.

A separate section records the round's own accident. A reviewer's cleanup
command killed the production router while verifying the exact hazard that
made it possible.

## Leaked credentials, misrouted requests

The router's local-header policy was written as an allow-list but worked
as a two-entry deny list. Cookie, every value in
`ANTHROPIC_CUSTOM_HEADERS`, and any future auth header reached the local
backend verbatim (HIGH, router review). A chunked request body was dropped
before the router could read a model name from it. With no model left to
route on, the request went upstream to production instead of failing
closed. It billed the seat's credential (HIGH, router review).

A colon-based heuristic used to pick the local backend also caught real
Bedrock ids and `:beta` Claude ids. Those requests should have gone
upstream; instead they went to the local model (MEDIUM, router review).

On the shell side, a backend could supply a model id that got inserted
into hand-built JSON without escaping. That let it redirect any local
prompt off the box (HIGH, shell/cost review). The API key rode in
`curl`'s argv every 10 seconds, readable to anything that lists processes.
A non-atomic config write left a window where the key sat in a
world-readable file. Masking in `status` covered keys of 12 characters or
more. The 11-character default key printed in full as a result (MEDIUM,
shell/cost review).

Separately, `backends.json` holds an API key outside sops, the project's
own standard for secrets (flow/docs review).

Fixed: the router (0.4.0) allow-lists headers instead of denying two. A
request naming an undeclared backend now gets a 404 instead of a guess. A
chunked body with no resolvable model gets a 411 instead of an upstream
pass-through. Ids naming a Claude model stay upstream regardless of the
colon heuristic.

The shell tools build JSON safely and write config atomically at mode
0600. The key passes through `--api-key-file` and `curl --config` instead
of argv. Every key length is now masked unconditionally. Unsloth backend
selection now matches the requested model instead of whichever one is
listed first.

## Silent failures

The most consequential one: a skill's `tools:` field is not a real
frontmatter key, so it is silently ignored. Both of the plugin's skills
granted nothing as a result. That included the Bash the fail-closed
preflight depends on to run at all (HIGH, plugin review).

Three reviewers independently found the same shape of bug in `down`. It
orphans the local or default backend, leaving no way back except
hand-editing JSON (flow/docs review, shell/cost review). The CLI review
found the same command leaves a stale default behind after cleanup.

`answering()` reported dead ports as alive. `curl` already prints `000` on
a failed connection, and the script's `|| echo 000` appended a second one.
The check always saw output, so it always read the port as alive (HIGH,
shell/cost review).

Two separate reviewers hit `--check` from different angles. The CLI review
found it had no verdict line, so a warn state read as ok. The router
review found it crashed outright on a non-JSON 200 response (see Hangs and
crashes, below).

On the CLI, default-backend FAIL rows carried no next action, while
optional-backend rows did. Duplicate router daemons accumulated with no
signal; three were alive at once. `status` truncated its rows to the
interpreter path. Its fallback branch, meant to print "(none)", was dead
code that never ran (CLI review).

Two items in the flow/docs review are stale by construction. The built-in
Explore override is a hardcoded duplicate of `agents/local-explore.md`
that can drift with nothing to catch it. A content-addressed blob sha
elsewhere is hardcoded the same way.

On the router, folding a request silently dropped non-text content blocks
and `cache_control`. A hostile body type killed the request with no
response sent and no row written to the ledger (MEDIUM, router review).

In cost accounting, `--since` silently discarded undated rows instead of
counting them. A summary figure omitted the cache-read tokens printed one
line above it. Rows with no recorded backend were merged into the real
"default" backend's totals (shell/cost review).

On the plugin side, `local-implement` never reported its own worktree
path. The caller had no way to find the edits it made as a result (MEDIUM,
plugin review). No agent description said that `local`/`default` only
resolves inside a routed session. The wrong session type fails without
saying why (HIGH, plugin review).

Fixed: allowed-tools is now set on both skills. `down` clears the matching
default. `answering()` no longer double-counts a failed probe. `--check`
now prints a verdict on both a warn and a non-JSON response.

Folding keeps `cache_control` and counts what it drops. A hostile body now
gets an answer and a ledger row. `--since` keeps and counts undated rows.
Unrecorded backends are bucketed separately instead of merged.

All five agent descriptions now state the routed-session precondition.
`local-implement` hands back its worktree path.

## Hangs and crashes

A backend dying mid-stream escaped the router's exception handling. The
chunked response was left with no terminator and no ledger row. A client
waits on a stream that will never close (HIGH, router review).

A non-dict backend value, a non-numeric environment variable, or a
`LISTEN` value with no colon crashed the router at import. That happened
before it could serve anything (HIGH, router review). `--check` crashed
outright on a non-JSON 200 response and printed nothing (MEDIUM, router
review).

Bodyless responses (HEAD, 204, 304) were framed as chunked. A strict
client can read that framing as a stream still waiting for a terminator
(MEDIUM, router review).

On the shell side, `claude-local`'s `chmod --` aborts under `set -e` on
BSD. This happens in the one branch that runs when the router is not yet
up. The path meant to bring the router up is the one most likely to fail
first (HIGH, shell/cost review).

In cost accounting, a valid-JSON line that was not an object crashed all
three cost lanes. A non-numeric usage value raised instead of being
coerced (shell/cost review).

Fixed: mid-stream death now sends an SSE error, a terminator, and a ledger
row. Malformed config is validated and rejected with a message instead of
crashing the router at import. `--check` survives non-JSON input and now
prints a verdict. Bodyless responses get correct framing.

`chmod` no longer aborts the router's own startup path. Non-object lines
are skipped instead of fatal. Usage values are coerced numerically.

## Documented as true, not measured that way

Design and README claims did not hold up against the record. `design/02`
sections 3.2 to 3.4 still asserted the conclusion its own section 3.6d had
reversed. The README still sold the MLX prefix cache after the measured
decision moved away from it. It also said "Two cost lanes" after a third
had already landed (CLI review, flow/docs review).

Test counts, tool lists, and environment-variable references were stale
against the code. `localrig`'s header claimed `claude-local` restarts the
router; it does not (CLI review, flow/docs review).

The Ollama version floor was stated as both 0.33.0 and 0.33.2 in different
places. The local lane's fresh-machine prerequisites, Ollama, the model
pull, the version floor, and llama.cpp, were stated nowhere. That included
Requirements and doctor (flow/docs review).

Four specific measurements did not survive a check against their own
source logs. A line reading "forcing full prompt re-processing, 7,201
tokens" was quoted for a run whose log does not contain it. The number
belongs to a different task. A claim that "the only difference is the
reminder" is contradicted by the dump it cites: system length runs 3682
tokens against 3629, a real difference beyond the reminder.

A headline 0.38-second figure was measured under flags `claude-local` does
not use in practice. A contradicting production run was left out of the
writeup. One more measurement was quoted three ways in three places: 5.3k,
6.3k, and 7.2k tokens. All three describe what should be a single number.

A prefill floor was raised from 87 to 120 tok/s with no run recorded
behind the new number. Separately, an n=1 caveat present in the design doc
was dropped when a number was copied into the README.

The fail-closed safety story had the same problem. The contract itself was
unfalsifiable. The model was told to run a preflight but never told to
show it. Two sanctioned escapes let it avoid going local while still
following the letter of its instructions (HIGH, plugin review).

The CLI review found the same preflight offered no remedy for its own
failure beyond "disable the safety check" (CLI review). The
prompt-injection warning was absent from the entire local lane.
`local-implement` holds Bash, Edit, and Write regardless (HIGH, plugin
review).

Fixed: three unsupported measurement claims were corrected in place. They
were the misattributed 7,201-token line, the "only difference is the
reminder" claim, and the 0.38-second headline. A superseded banner now
sits over `design/02` 3.2-3.4.

Stale counts, lists, and false claims were corrected, including
`localrig`'s header and "Two cost lanes." Local-lane requirements,
including the version floor and the fresh-machine prerequisites, are now
stated once in Requirements and doctor.

The prefill floor now reads 87 to 230 tok/s in the README, matching the
bench in design/01 (fixed, commit f76247a era). The n=1 caveat is now
restored. The 54-tool figure in the README carries "that agent's turn two
repeated the full prefill, cause not isolated, n=1".

The agent instructions add a mandatory, verbatim preflight line and an
injection warning to the local lane. The `claude-local` preflight message
was rewritten. It no longer offers only "disable the safety check." It now
names the FAIL rows as the cause.

It gives three options. Fix the row and rerun. Start with
`CLAUDE_LOCAL_SUBAGENT=sonnet` so subagents run on sonnet instead of
locally, or set `CLAUDE_LOCAL_NO_PREFLIGHT=1` to start anyway and let
local calls fail.

## Smaller findings, same round

A Bash allow-rule pattern matched nothing. Two agents were assigned
overlapping jobs. Both were corrected on the plugin surface (MEDIUM,
plugin review). `local-test` was instructed to echo 60 lines of log at 15
tokens a second. It now logs to a file instead (MEDIUM, plugin review).

The cost tool loaded its entire ledger into memory for every query. It now
reads as a stream instead (shell/cost review). The shell tools had no
`--help` or `--version` flag. Both are now present (CLI review).

Both remaining MEDIUM items were closed after this document was first
drafted. The preflight accepted any loopback address, so a LiteLLM or
corporate proxy on 127.0.0.1 satisfied it. It now also requires the
address to match the `router` row of `agentroute --check`. `local-implement`
carried `maxTurns: 40`, which is 20 to 40 minutes at this model's speed.
It is now 20, and the fix loop was already capped at two retries.

## What held up under review

The router review also verified invariants and reported them as sound.
Twelve simultaneous streams held a peak of exactly 2 requests in flight,
with no corruption. The semaphore never leaked under load. The seat token
never reached the ledger. The router ran clean on python 3.9.

## The self-inflicted incident

The shell/cost review flagged `pkill -f` as a blast-radius hazard (HIGH).
It kills every process whose command line matches the given pattern, not
only the one process a script means to stop.

While reproducing that exact finding, the reviewer ran a verification
command: `pkill -f 'agentroute --serve'`. That command matched the shell
command containing the same string. It killed the production router along
with the throwaway process it was meant to test. The hazard stopped being
theoretical the moment the review demonstrated it against its own target.

Three daemons already orphaned by the duplicate-daemon finding above were
cleared as a side effect. The router was restored afterward.

The same process-matching fragility runs through three findings in this
round. The CLI review found `restart-router` killing the wrong process on
a stale port. The shell/cost review found the same `restart-router` can
abort before it restarts anything. This incident is the third.

All three are fixed the same way. Pidfiles with argv verification replace
`pkill` for process identification. `restart-router` now verifies a
process before it kills it.

## Current state

A flaky test surfaced after the round closed. `tests/test-agentroute.py`
failed 86 of 87 under `make test`, then passed 87 of 87 three times run in
isolation. The cause was a load-sensitive assertion that required zero
keep-alive pings on a fast response. Under back-to-back suite runs, a
response can legitimately cross the ping threshold, at which point a ping
is correct. The assertion now requires zero pings only when the response
actually beat the threshold. Two full `make test` runs have been clean
since.

All suites are green except the one pre-existing fanout check, in an
untouched file, that predates this round. The router suite holds 87
checks. The cost-accounting suite holds 50.

The live router is restarted on 0.4.0. A health check reads 8 ok / 0 warn
/ 0 FAIL. A request naming an undeclared backend is rejected with a
message naming what is declared. A real local call still answers. The
change is committed and pushed.

## For the next round

Grouping by defect kind instead of by reviewer surfaced three patterns.
The same bug was found independently three times: `down` orphaning a
backend. The same command was hit twice from different angles: `--check`.
The same root cause sat behind three different findings: fragile process
matching around `pkill`.

Look for that pattern first. A bug that three reviewers hit from three
angles is worth more than eleven bugs one reviewer found alone.

The self-inflicted incident is the strongest evidence in this round. It
argues for treating review tooling as production-adjacent. A throwaway
verification command ran in the same process namespace as the system
under test, with no isolation between them.

The next round should reproduce findings against a router instance that
cannot be the production one, by port, container, or host. That way, a
cleanup command can only ever reach its own target.
